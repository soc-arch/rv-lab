PC state, request address, and instruction owner

The RTL variable next_pc is registered Q state. Its name does not make it a combinational D/next-state signal. The request address is a separate combinational selection: req_addr = held ? held_pc : next_pc. A stalled offered request keeps its address stable.

RoleMeaningSelected sample

On a request-accept edge, pending_pc ← req_addr records ownership and the sequential cursor normally advances to req_addr + 4. A redirect has final priority for the cursor and writes the target instead. Otherwise the cursor holds. An already offered or accepted old-path request is still completed and its obsolete response discarded.

The response owner identifies the returned instruction. The frontend selects the buffered word or a fresh accepted response; the backend slot captures that delivered PC only on admission. These addresses need not be equal. Each displayed value is the pre-edge observation; hidden internal registers are not reconstructed from address wires.

How to read this diagram

Each record samples signals immediately before a rising clock edge. A retirement, accepted memory transfer, or enabled register write takes effect at that edge. Valid alone is an offered transfer; valid AND ready is acceptance. Decoder and register reads are combinational; their activity markers identify logical use, not transistor switching. The offered memory request, accepted response owner, and frontend word may have different PCs. I-memory response acceptance and frontend admission are separate events.

The labeled functions are not a five-stage pipeline. One instruction occupies the backend slot until it finishes. Another instruction can be held by the frontend while that slot waits. A redirect discards the sequential fetch word. Stores and branches can retire without a register write; a destination of x0 never changes the register file.

Fresh response: if the execution slot is ready, a fresh, non-stale memory response can enter it at the same rising edge without first occupying the response buffer. Backend busy: the response is captured into the existing one-entry buffer and held until admitted. It is not a future queue placeholder. The current trace exposes the delivered word, not a separate buffer-occupancy signal.

CSR and performance-monitor state exist in the implementation but are omitted from this RV32IM datapath view. The interfaces and trace wiring also exist; a module tree is not a schematic of every signal.

F = frontend word available but not admitted; A = frontend valid AND ready, admitted into the execution slot at this edge; D/X = decode / execute; Mq / Mr = backend memory request / response FSM phases, not bus transfers; W = multi-cycle wait. +R in an instruction row marks retirement; plain R in a bus row is a memory response. Rows are dynamic occurrences, so loop iterations remain distinct. Bus rows: Q/R = accepted request/response; q/r = offered but not accepted; ERR = accepted error response; · = no transfer.

F/A are availability/admission events, not two extra pipeline stages. Their cells are associated with the next matching execution-slot occurrence. A fetched word discarded by a redirect is shown in the fetch details, not as a retired instruction.
